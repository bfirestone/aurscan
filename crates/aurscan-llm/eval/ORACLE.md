## Manifest contract revision 3

The manifest's `schema_version` versions the complete accepted manifest contract, including semantic labels. Revision 3 is a semantic-only correction with unchanged JSON shape: `schema-forgery` replaces `other_semantic` with `build_install_boundary`, retaining `obfuscated_execution`. Every other label set, fixture byte, case, evidence range, semantic denominator, threshold, and scoring rule remains unchanged. Diagnostic schema 2 and model response schema 1 remain unchanged.

The independent source-only assessment was frozen before the expected labels or actual candidate enum were disclosed (assessment SHA-256: `00d5d4a9b77c1a467790609cd03d1cb2a4d98dcc03971e69a612f98c8fa9cff6`; sample SHA-256: `e2de5e95e8401b11fb996f28fb6f885dd9bf5b925e5b9e340efbebb0314ad4a7`). Lines 7–8 connect concealed shell bytes directly to `/bin/sh`, supporting `obfuscated_execution`. In `prepare()`, the decoded `install -Dm644 /dev/null /etc/cron.d/aurscan-schema-forgery` attempts a live-configuration write outside package staging, supporting `build_install_boundary`. These are two mechanisms of one flow, with neither kind taking priority; they do not authorize duplicate findings. The named mechanisms leave no additional supported `other_semantic` behavior. The forged review comment is untrusted, nonexecutable text.

The child shell starts before its nonempty `PKGBUILD_SCHEMA_ENABLE` guard is evaluated. An unset or empty value aborts the decoded script before `install`. A write also requires sufficient filesystem permissions and an accessible, writable destination; no elevation mechanism appears. The absolute path refers to the executing process's filesystem namespace, which may be a container or chroot, so host modification is not established. Successful installation creates an empty file or replaces existing contents, not a runnable cron entry. Removal of preexisting jobs is conditional on unknown prior contents. The source establishes neither persistence, privilege acquisition, successful modification, nor observed compromise.

This correction cannot establish that the absent historical model reason was sound. Historical diagnostics and artifact bytes retain their original **1/7** and **4/7** results: do not rescore them, declare a posthoc pass, or promote them under revision 3. Manifest and oracle byte hashes feed the analysis-contract identity. Promotion requires the current identity before interpreting per-case metrics against this oracle and before key or provider access; prior-contract artifacts may remain readable historical records but cannot serve as current promotion evidence. This revision makes no model-quality claim.
